# write-feature

Оркестратор (`spec-orchestrator`) строит план, уточняет блоки у пользователя
и вызывает `spec-writer` **по одному блоку**. Этот скилл — правила **одного**
фрагмента.

Пути: правило `artifact-paths`. Таблица блоков и код → скилл: [reference.md](reference.md).

| | Путь |
|---|------|
| **Вход блока** | бриф + `CONTEXT_DOC` + скиллы из колонки плана |
| **Выход блока** | `FEATURE_DIR<slug>.part-<block_id>.md` |
| **Сборка** | оркестратор даёт отдельное задание assemble → `SPEC` |

## Один блок

1. Загрузи **все** kit-скиллы из колонки плана — не больше и не меньше.
   Нет скилла в колонке → не вызывай его, даже если другой скилл блока его упоминает.
2. Для каждого скилла колонки прочитай его template / example / gate **целиком**
   из `kb-writing-kits/` (чтение файла, не `head`).
3. Прочитай `CONTEXT_DOC` и `<slug>.context.md`, если есть.
4. Проход 1: только бриф, контекст, kit. Нет факта → `[GAP-...]`.
5. Проход 2: гэпы по якорям `CONTEXT_DOC` или `find_context.py`; не нашёл — оставь.
6. Фрагмент → `<slug>.part-<block_id>.md`; допиши в `<slug>.context.md`.
   `check-part` на первом проходе не вызывай (оркестратор — один раз).
   Повтор после отказа: один `check-part` с `--block-id` и `--sections` из задания.

Формат фрагмента и гэпы — [reference.md](reference.md). Форма раздела —
только template и gate kit: не добавляй подразделы сверх kit и не выкидывай
то, что kit требует.

## Assemble (только по заданию оркестратора)

```bash
python3 scripts/write_feature.py "<бриф>" --mode assemble --name <slug> \
  --sections "<утверждённый план>" \
  --part-dir Feature-writing/<slug> \
  --out Feature-writing/<slug>/<slug>.md
```

Успешный `--out` удаляет `*.part-*.md` и `*.context.md`.
Незакрытые гэпы не выдумывать. Лимит строк на `SPEC` не действует.

## Антипаттерны

- ❌ Писать всю spec в одной сессии `spec-writer`
- ❌ Фрагмент без вызова скиллов из колонки плана и без чтения их файлов из `kb-writing-kits/`
- ❌ Догружать kit-скилл, которого нет в колонке плана
- ❌ Обрезать kit (`head` / `tail`)
- ❌ Соседняя спека как образец полноты
- ❌ Внутренние классы в Use Case; сжимать форму относительно kit
- ❌ Выдумывать факты / удалять `[GAP-...]`
- ❌ Считать блок готовым, если `check-part` вернул отказ
- ❌ Второй `check-part` на тот же блок; вызов без `--block-id` или `--sections`
