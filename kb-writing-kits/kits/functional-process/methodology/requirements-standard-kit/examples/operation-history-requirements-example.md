#### Анализ требований — Получить историю событий

**Источник требования:**

| Параметр | Значение |
|----------|----------|
| Фича | Получить историю событий |
| Источник | Product request |
| Инициатор | Product Owner мобильного банка |
| Дата / версия | Draft 2026-05 |

**Стейкхолдеры:**

| Стейкхолдер | Роль | Интерес / ожидание | Влияние / ответственность |
|-------------|------|--------------------|---------------------------|
| Клиент мобильного банка | Основной пользователь | Видит актуальную историю событий на экране | Использует результат фичи |
| Product Owner мобильного банка | Владелец продукта | Получить единый экран истории событий из разных источников | Принимает функциональный результат |
| Команда BDUI | Владелец экранного сервиса | Получить агрегированные данные для формирования экрана | Формирует экран и отдает его фронту |
| Команда backend истории событий | Владелец агрегации | Собрать события из источников и вернуть согласованный набор данных | Реализует агрегацию и обработку ошибок |
| Владельцы источников событий | Поставщики данных | Передать события в согласованном формате | Отвечают за полноту и корректность данных источников |

**Бизнес-правила и ограничения:**

| ID | Тип | Описание | Источник / обоснование |
|----|-----|----------|------------------------|
| BR-01 | Бизнес-правило | История событий должна формироваться из шести источников данных по операциям | Product request |
| BR-02 | Бизнес-правило | Backend агрегирует полученные сообщения перед передачей данных в BDUI | Product request |
| BR-03 | Бизнес-правило | BDUI формирует экран истории событий на основе агрегированных данных | Product request |
| CN-01 | Ограничение | Обмен между backend и источниками выполняется асинхронно через Kafka | Product request |

**Цель фичи:**

| Вопрос | Ответ |
|--------|-------|
| Какую бизнес-проблему решает? | Сейчас пользователю нужен единый экран истории событий, но данные событий находятся в нескольких источниках |
| Какую ценность приносит пользователю? | Пользователь получает собранную историю событий в одном экране без ручного перехода между источниками |

**SMART-проверка цели:**

| Критерий | Описание | Значение |
|----------|----------|----------|
| Specific | Конкретная | Реализовать получение истории событий через BDUI и backend с агрегацией данных из шести источников |
| Achievable | Достижимая | Достижимость зависит от готовности Kafka-взаимодействий и контрактов шести источников |
| Relevant | Релевантная | Фича напрямую влияет на пользовательский доступ к истории событий |
