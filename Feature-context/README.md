# Feature-context

Рабочая папка скилла `find-context`. Здесь хранятся документы «Контекст для
фичи»: проверенные факты из аналитики, спецификаций, кода и данных, которые нужно
учесть при написании фичи.

## Назначение

**Ориентированный на задачу срез current-state контекста** под конкретный бриф —
не документ фичи и не проектирование решения.

Связь с `Feature-writing/`: `find-context` готовит контекст, `write-feature`
по нему (и по `kb-writing-kits/spec-catalog.yaml`) пишет спецификацию в `Feature-writing/<slug>/`.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `<slug>-discovery.md` | INTERNAL-пакет от helper: поисковые термины и ранжированные кандидаты. Рабочий артефакт, можно удалять. |
| `<slug>.md` | Готовый документ «Контекст для фичи»: проверенные находки, что учесть, открытые вопросы `Q-XX`. |

## Обратная связь от спецификации

Контекст-документ **не отстаёт** от spec: все `/resolve-*` скиллы дописывают
закрытые вопросы в секцию `## Закрытые вопросы`:

```markdown
## Закрытые вопросы

| ID | Дата | Решение | Где в spec | Источник |
|----|------|---------|------------|----------|
| Q-04 | 2026-08-28 | Доходность в `HistoryOperationLead.yield` | §4.1.1, §4.2.3 | /resolve-gaps (GAP-INT-05) |
```

Строки из «Открытые вопросы» при этом **не удаляются** — история сохраняется, а
`/feature-status` считает открытые Q как разницу двух секций. Прочие § документа
resolve-скиллы не меняют.

## Области поиска

| Область | Путь | В поиске |
|---|---|---|
| Аналитика (Confluence) | `analytics/` | Да — бизнес-факты, приоритет |
| Спецификации фич | `Feature-writing/*/` | Да — reference, sibling-фичи |
| Код и контракты | `repositories/` | Да — технические факты, приоритет |
| Данные | `db-export/` | Да — справочник схемы |
| Доп. материалы | `auxiliary/` | Да (если есть) |

## Как сюда писать

Через `/find-context` или напрямую скриптом:

```bash
# 1. Поиск кандидатов
python3 scripts/find_context.py "<бриф>" --name <slug> --out Feature-context/<slug>-discovery.md

# 2. Агент проверяет находки по файлам и заполняет скелет → Feature-context/<slug>.md
```

Скрипт пишет § «Фокус поиска»: для интеграций сначала `.proto` / RPC, для
данных — liquibase / `db-export/`. Нет якоря → `Q-XX`.

После `/resolve-*` запускается `scripts/refresh_context.py`: обновляет только
§ «Что учесть», current-state не переписывает.

Правило: **факт без пути и якоря — не факт**, а `Q-XX`.
