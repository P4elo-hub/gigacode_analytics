# Что доделать для конкурентоспособности

Не расширять решение вширь слишком рано. Сначала довести до сильного состояния то, что отличает продукт от `n8n`, скриптов и самописных оркестраторов: управление CLI-агентами как короткими, контролируемыми шагами над файлами проекта.

## 1. Killer-demo граф

Довести один демонстрационный граф до блеска:

`Brief/Jira -> context -> spec -> gaps -> challenge -> code alignment -> PASS`

В demo должны быть:

- тайминг прогона;
- логи шагов;
- итоговый документ;
- сравнение с ручной работой;
- понятный вход и выход.

Без этого продукт выглядит как абстрактный graph builder.

## 2. Установка за 10 минут

Сделать быстрый путь для нового пользователя:

- одна команда установки;
- примерный репозиторий;
- sample task;
- поднятый `pipeline-viewer`;
- demo-прогон без чтения всей внутренней документации.

Цель: человек должен увидеть пользу до того, как начнет разбираться в архитектуре.

## 3. Pack template для чужого процесса

Подготовить шаблон, из которого можно за вечер собрать свой маленький граф:

- `agents/`;
- `skills/`;
- `graph.yaml`;
- `routing_conditions.yaml`;
- quality gates;
- пример папки дела;
- минимальный README для автора нового pack.

Это должно заменить необходимость изучать весь текущий workspace.

## 4. Жёсткая изоляция скиллов

Сейчас хук блокирует чужого агента, но не полностью блокирует чтение чужого скилла.

Нужен режим, где в сессию физически доступны только skills текущего шага. Это может стать сильным отличием от `n8n` и простых shell-скриптов.

## 5. Метрики результата

В `pipeline-viewer` нужно показывать не только граф, но и доказательство контроля:

- сколько было шагов;
- сколько ретраев;
- где были divergence;
- сколько GAP закрыто;
- сколько было ручных вопросов;
- сколько времени прошло до PASS;
- где процесс тормозил.

## Позиционирование

Не начинать с маркетплейса графов. Сначала доказать, что один граф настолько полезен, что люди захотят собрать свой.

Рабочая формулировка:

> Control plane for CLI agents: run Qwen/Claude/OpenCode workflows as short, gated, observable steps over your repo.
