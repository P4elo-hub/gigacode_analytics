            Инфраструктура (не узлы графа)

            Hook, validate и set_active_task оборачивают каждый subagent — отдельными узлами на схеме не рисуются. 

            dispatch --json
  → set_active_task
  → task (subagent)
  → [SubagentStop hook]
       append_run_log → ingest → validate
  → dispatch → task …

            На графе: квадрат = шаг агента · овал = analyze-routing после шага · зелёный = ok · серый = не было в логе · розовый = redo после restart · фиолетовая рамка = dispatch next.

                Выбранный шаг

                Клик по узлу на графе. Жёлтая/оранжевая рамка — есть замечания.

                Кликните узел на графе.

                Кликните клетку — исходящие стрелки. Кликните стрелку — условие перехода.

                Пауза на этой клетке: вопрос и apply без смены шага. Не стройте переход «на другого агента» между вопросом и apply — стрелки с клетки срабатывают только после apply.

                cycle

                Одна клетка. Внутри — очередь вызовов по порядку, без стрелок и analyze-routing.

                Очередь вызовов

                Спросить по calls этой клетки — тем, что перечислены ниже. Не каталог и не чужой профиль.

                Те же calls, без вопроса: всегда этот порядок.

                calls

                  Выход из клетки: когда очередь calls закончилась, движок ставит отметку на этом шаге и снимает активную задачу. Дальше — внешний dispatch по стрелкам с этой клетки. close = on_done, набор не редактируется.

                  • main — основной ход вперёд, счастливый путь (сплошная линия).
                  • branch — ветка по условию, не главный шаг (пунктир).
                  • loop — возврат: перепроверить шаг или освежить routing (точки).
                  Тип перехода

                  Bool — факт из routing-state. «После шага» — петля к analyzer без when: has_agent_zakonchil_….

                  условие перехода (bool)

                    Петля «после завершения»: в YAML не будет when: bool. Движок после шага увидит stale routing-state и снова вызовет analyze-routing.

                    Пишите условие обычным текстом. При «Проверить» / «Применить» система сама придумает id (has_…), запишет его в status_fields.instruction = ваш текст, создаст edge_conditions и строку dispatch (priority + when).

                    Только с этой клетки. Клик по строке — открыть условие на стрелке.
